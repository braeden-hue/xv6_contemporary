Steady-state pattern (from sample ~5 onward) is a clean, deterministic
staircase: worker0 open_wait_ticks=2, worker1=1, worker2=0, all three
wait_ticks_max pinned at 3. This is exactly what a stable 4-participant
1-tick round robin (worker0, worker1, worker2, sampler, repeating) predicts:
each worker waits exactly 3 ticks (the other 3 participants' turns) between
its own dispatches, and at the instant the sampler runs, worker0 has had 2
of those 3 ticks elapse since becoming RUNNABLE (it ran first, longest ago),
worker1 has had 1, and worker2 (ran immediately before the sampler) has had
0 -- reproducing the exact "adjacent-to-sampler reads 0" finding from v1 of
this test (2 workers, single target queried), but now alongside two other
workers that clearly show open_wait_ticks > 0, proving the RUNNABLE-branch
of sys_sched_stats() (kernel/sysproc.c) is correct and it was v1's specific
adjacency that produced the all-zero result, not a code defect.
